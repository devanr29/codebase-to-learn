===============================================================================
 codemap explore  --  step-by-step tutorial
===============================================================================

`codemap explore` turns the symbol graph in .codemap/index.db into ONE
self-contained file, .codemap/explore.html, that you open in a browser. No
server, no build step. Four tabs: Graph, Map, Learn, Timeline.

All commands below assume you are in the repo root. This project ships a virtual
environment at .venv, so the Python is:

    .venv/Scripts/python -m codemap <command>

If you have installed codemap globally (see section 11) you can drop the prefix
and just type:  codemap <command>


-------------------------------------------------------------------------------
 1. Check the tool runs
-------------------------------------------------------------------------------

    .venv/Scripts/python -m codemap status

On the first run this creates the .codemap/ directory and a config.toml.
If it prints "index: empty", that is expected -- go to step 2.


-------------------------------------------------------------------------------
 2. Index the repository
-------------------------------------------------------------------------------

    .venv/Scripts/python -m codemap scan

This walks every commit since the last one it saw, parses the files that
changed, and stores the symbol graph in .codemap/index.db. The first run
indexes the whole history. Re-run `scan` whenever you have committed and want
the explorer to reflect it.


-------------------------------------------------------------------------------
 3. Generate and open the explorer
-------------------------------------------------------------------------------

    .venv/Scripts/python -m codemap explore --open

Writes .codemap/explore.html and opens it in your browser. Drop --open to just
write the file. The file is fully self-contained: copy it anywhere, send it to
someone, commit it in another repo -- it needs nothing else to work.

Useful flags:
    --out <path>       write somewhere other than .codemap/explore.html
    --quiet            no summary line
    --max-symbols N    cap graph nodes (default from config; see section 9)
    --json             print the raw graph model as JSON and write nothing
    --emit-brief       write the analysis pack for the Learn course (section 7)


-------------------------------------------------------------------------------
 4. The Graph tab  (the main page)
-------------------------------------------------------------------------------

LEFT RAIL -- the whole source tree.
    * click a folder to expand / collapse
    * click a file to expand its functions
    * click a function to focus it
    * the number on each row is that symbol's caller count
    * press Ctrl+K (Cmd+K on Mac) for fuzzy search over every symbol

CENTRE CANVAS -- the neural graph.
    * the Package / Module / File / Function buttons change what a dot means
    * drag the background to pan; scroll to zoom
    * the + / - / recenter buttons are bottom-left
    * click any dot (or a tree symbol) to FOCUS it

FOCUS = the neuron view.
    The focused symbol sits in the middle. Everything that CALLS it fans out to
    the left (afferent dendrites); everything IT calls fans to the right
    (efferent). The "hops" slider in the top bar grows the dendrites one call
    hop at a time. The "Whole graph" button clears the focus.

RIGHT INSPECTOR -- for the focused symbol:
    * fan-in / fan-out counts
    * a file-anatomy strip: the whole file as a bar, each symbol a block at its
      real line range, coloured by kind -- the empty gaps are module-level code
    * a blast-radius bar: "editing this reaches N callers across M files"
    * the shortest path from an entry point (e.g. GET /report -> ... -> fetch)
    * a "Trace calls from here" link into the Map tab's Run trace (section 5)
    * the symbol's source, and an "Open in editor" link

LEGEND (bottom-right) -- read this:
    * purple edge  = a same-file call the tool is confident about (tier 2)
    * grey edge    = a cross-file guess by name (tier 1, may be over-broad)
    * module-level calls are NOT drawn at all
    Nothing is ever labelled "dead" -- only "no inbound edge at tier N".


-------------------------------------------------------------------------------
 5. The Map tab  (structure, not connections)
-------------------------------------------------------------------------------

The Graph tab answers "what calls what". The Map tab answers three questions it
doesn't: what SHAPE is the system, what happens when it RUNS, and where is the
code. Three views, switched with the buttons at the top left. Everything is
built from the same graph -- no extra step, no extra data.

LAYERS -- the dependency skeleton.
    Files are stacked into layers by their in-repo imports: L0 at the bottom
    imports nothing else in the repo (config, logging, small helpers), each
    layer above imports only from below, entry points end up at the top.
    * block width  = lines of code
    * block colour = folder (same colours as the Graph tab legend)
    * a block marked with a loop arrow is an IMPORT CYCLE -- several files that
      import each other, collapsed into one block; hover it for the members
    * hover any block to light up what it imports (downward) and what imports
      it (upward)
    * click a block to jump to that file in the Graph tab
    * "Hide tests" drops tests/** so the production skeleton stands alone

RUN TRACE -- one call chain as a subway map.
    Pick a starting function from the dropdown (they are ranked by how much
    they reach). Columns are call depth: the root on the left, what it calls
    in the next column, and so on.
    * dot size    = how many callers that function has
    * dot colour  = folder
    * "+ N more calls" appears when a column is busy; click to expand it
    * the < and > buttons step a highlight one hop at a time, so you can watch
      the cascade instead of reading a wall of lines
    * a lightning-bolt card means the chain hit a call the indexer can't
      follow statically -- e.g. a CLI's `args.func(args)`, where the real
      target is chosen at runtime. The trace stops there ON PURPOSE and tells
      you, rather than pretending the function is a dead end.
    In the Graph tab's inspector there is a "Trace calls from here" link that
    opens this view on the focused symbol.

MASS -- a treemap of the whole repo.
    * rectangle area = lines of code, grouped by folder
    * fill          = how many commits have touched the file (darker = quiet,
      brighter = changes a lot)
    * a hatched rectangle = every function in that file is unreachable at the
      current tier -- a candidate for deletion, or a sign of missing edges
    * click a rectangle to open the file in the Graph tab


-------------------------------------------------------------------------------
 6. The Timeline tab
-------------------------------------------------------------------------------

Newest commit first. Each card shows:
    * the stated intent and where it came from (commit message / note / session)
    * coloured bars: structural / behavioral / cosmetic change counts
    * the headline change and its blast radius
    * any new dependency

Click "Read this first: ..." on a card to jump straight to that symbol in the
Graph tab.


-------------------------------------------------------------------------------
 7. The Learn tab  (guided course)
-------------------------------------------------------------------------------

Out of the box the Learn tab shows a generated ORIENTATION: entry points, the
module map, and the highest-traffic symbols to read first.

To get a full guided course (module narratives, plain-English code
translations, quizzes, glossary tooltips):

    a) Emit the analysis pack:

           .venv/Scripts/python -m codemap explore --emit-brief

       This writes .codemap/briefs/  --  00-overview.md plus one file per
       module, each with pre-extracted code snippets.

    b) In Claude Code, invoke the skill:  /codebase-to-course
       (or just ask: "turn this codebase into a course"). It reads the briefs
       and references/, then writes .codemap/learn.json.

    c) Re-render:

           .venv/Scripts/python -m codemap explore --open

       The Learn tab now shows the authored modules instead of the Orientation.

If learn.json is ever malformed, the tab silently falls back to the Orientation
-- nothing breaks. If your course "isn't showing up", validate the JSON first.


-------------------------------------------------------------------------------
 8. Keep it fresh automatically  (optional)
-------------------------------------------------------------------------------

    .venv/Scripts/python -m codemap install-hook

Installs a post-commit hook that runs scan -> explain -> explore in the
background after every commit, so explore.html is always current. It can never
block or fail a commit.

To turn the auto-rebuild off for this repo, set in .codemap/config.toml:

    [explore]
    rebuild_on_commit = false

Manual `codemap explore` still works when this is false.


-------------------------------------------------------------------------------
 9. Config knobs  (.codemap/config.toml)
-------------------------------------------------------------------------------

    [explore]
    rebuild_on_commit = true    # does the post-commit hook rebuild the page
    max_symbols       = 1500    # graph node cap; over this the graph drops to
                                #   file-level and the page says so. The tree
                                #   and file list stay complete.
    max_snippet_lines = 40      # longest source excerpt embedded per symbol


-------------------------------------------------------------------------------
 10. Run against a different repository
-------------------------------------------------------------------------------

--path works on every subcommand:

    .venv/Scripts/python -m codemap scan    --path ../other-repo
    .venv/Scripts/python -m codemap explore --path ../other-repo --emit-brief
    .venv/Scripts/python -m codemap explore --path ../other-repo


-------------------------------------------------------------------------------
 11. Running without the ".venv/Scripts/python -m" prefix
-------------------------------------------------------------------------------

OPTION A -- install codemap as its own command (recommended):

    pipx install codemap          (or: uv tool install codemap)

Then just:  codemap scan  /  codemap explore  from anywhere. This is also what
install-hook assumes (codemap on PATH). To install THIS checkout instead:

    pipx install --editable "C:/Users/devan.ramadhana/Documents/Claude Skills/vibe-code-learn"

OPTION B -- activate the venv for your shell session:

    .venv\Scripts\activate        (PowerShell / cmd)
    deactivate                    (to disconnect again)

OPTION C -- call the venv's console script directly:

    .venv\Scripts\codemap scan
    .venv\Scripts\codemap explore --open


-------------------------------------------------------------------------------
 12. Troubleshooting
-------------------------------------------------------------------------------

Yellow "Built from ... HEAD is now ..." banner
    You have committed since the last render. Run `codemap explore` again.

Icons show as empty boxes
    You are offline. The Inter font and Phosphor icons load from a CDN
    (fonts.googleapis.com, unpkg.com). The page still works fully -- it just
    falls back to a system font.

"index is empty" / "no index yet"
    Run `codemap scan` first.

A function you expected shows no callers
    Check the tier badge in the inspector. "No callers at tier 1" means
    name-based resolution could not see them (aliased imports, dynamic
    dispatch), not that none exist.

The generated page never contacts the internet except for those two CDN
stylesheets. The optional LLM narrative stage ([llm] enabled = false by
default) is the only thing that would call an API, and the explorer never
uses it.
